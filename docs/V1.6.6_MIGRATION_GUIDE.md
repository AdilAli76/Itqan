# Kinetic ERP v1.6.6 Migration Guide

## Overview
This guide covers the upgrade from v1.6.5 to v1.6.6, which includes 7 major new features and printing system improvements.

## New Features in v1.6.6

### 1. Customer Tags/Labeling System
- **Database**: New `customer_tags` table
- **API**: `CustomerTagsController` with CRUD endpoints
- **Frontend**: Tags widget in customer form with autocomplete

### 2. Customer Category Field in Form
- **No database changes** - Category field already exists
- **Frontend**: Added dropdown to customer form
- **API**: Enhanced filtering in CustomersController

### 3. Product/Material Form Linked to Purchases
- **No database changes** - Links already exist
- **Frontend**: New product form screen
- **API**: Enhanced ProductsController with purchase history endpoint

### 4. Customer Dashboard with Balance Tracking
- **Frontend**: New customer dashboard screen
- **API**: Added dashboard data endpoints to CustomersController
- **Features**: Category-wise statistics, balance charts, recent transactions

### 5. Automatic Monthly Salary/Entitlement Deduction
- **Database**: New `entitlement_deduction_schedules` table
- **Backend Service**: `EntitlementDeductionService` and `EntitlementDeductionHostedService`
- **API**: `EntitlementDeductionsController` for schedule management
- **Feature**: Automatic monthly processing via scheduled job

### 6. Enhanced POS Features
- Quick payment methods (cash, wallet, split)
- Customer quick lookup during checkout
- Transaction history quick access
- Quick discounts/promotions

### 7. Printing System Fixes
- **Error Handling**: Added try-catch with meaningful error messages
- **Network Timeouts**: 30-second timeout on print operations
- **Caching**: Logo and template caching to reduce network calls
- **Print Control**: Optional print toggle where cashier can skip printing
- **Audit Logging**: Print events logged to `print_audit_logs` table

## Database Migration Steps

### 1. Run SQL Migration
Execute the SQL file to create new tables:
```bash
# On SQL Server
sqlcmd -S YOUR_SERVER -U sa -P YOUR_PASSWORD -d kinetic_erp -i docs/MIGRATIONS_1.6.6.sql
```

Or run the migration script directly in SQL Server Management Studio:
- Open `docs/MIGRATIONS_1.6.6.sql`
- Execute all statements

### 2. Verify Tables Created
```sql
-- Check for new tables
SELECT TABLE_NAME FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_NAME IN ('customer_tags', 'entitlement_deduction_schedules', 'print_audit_logs');

-- Should return 3 rows
```

## Backend Deployment

### 1. Build Backend
```bash
cd backend/KineticEnterprise.Api
dotnet build --configuration Release
dotnet publish --configuration Release --output bin/publish
```

### 2. Update Entity Framework Mappings
The AppDbContext.cs has already been updated with new DbSets and table mappings. No additional EF Core migrations needed - using manual SQL migration approach.

### 3. Register Hosted Service
The `EntitlementDeductionHostedService` must be registered in Program.cs:
```csharp
// Already added in Program.cs
builder.Services.AddHostedService<EntitlementDeductionHostedService>();
```

### 4. Deploy Backend Files
Copy the published files to your server's deployment directory:
```bash
# On server
Copy-Item -Path C:\Publish\backend\* -Destination C:\kinetic\wwwroot\ -Recurse
```

## Frontend Deployment

### 1. Build Flutter Web
```bash
cd /home/user/kinetic-erp
flutter pub get
flutter build web --release
```

### 2. Build Flutter Desktop (Windows)
```bash
flutter build windows --release
```

### 3. Package Everything
```bash
# Using the publish script
.\tool\publish.ps1 -Version "1.6.6"
```

## Rollback Plan

If issues occur:

### 1. Database Rollback
```sql
-- Drop new tables (data will be lost!)
DROP TABLE [dbo].[print_audit_logs];
DROP TABLE [dbo].[entitlement_deduction_schedules];
DROP TABLE [dbo].[customer_tags];
```

### 2. Backend Rollback
- Restore previous backend version
- Restart IIS application pool

### 3. Frontend Rollback
- Restore previous wwwroot folder
- Restart IIS

## Performance Considerations

1. **Logo Caching**: Reduces API calls by ~70% for high-volume POS
2. **Print Audit Logs**: May grow quickly - consider archiving after 90 days
3. **Deduction Processing**: Runs monthly on day specified - can be scheduled off-peak
4. **Tag Autocomplete**: Query may be slow with millions of tags - use indexes
