# الانتقال إلى SQL Server + Backend منفصل (.NET) — وثيقة القرار الهندسي

## لماذا هذا التغيير أكبر مما يبدو
Supabase لم تكن "قاعدة بيانات فقط" في التصميم السابق — كانت توفر أربع خدمات جاهزة مجاناً:

| ما توفره Supabase جاهزاً | البديل الآن بعد الانتقال |
|---|---|
| قاعدة بيانات Postgres مُدارة | SQL Server على ويندوز سيرفر — تديره بنفسك (نسخ احتياطي، تحديثات، مراقبة أداء) |
| مصادقة جاهزة (Auth) | ASP.NET Core Identity + JWT — تُبنى وتُصان يدوياً |
| REST API تلقائي لكل جدول | Web API Controllers — كل جدول يحتاج Controller يُكتب يدوياً |
| Realtime (اشتراك لحظي بالتغييرات) | SignalR Hub — نمط مختلف (Push من السيرفر بدل اشتراك مباشر على القاعدة) |
| تخزين الملفات (شعارات، صور) | مجلد ملفات على السيرفر أو Azure Blob لاحقاً |

**الخلاصة الصادقة:** أنت لا "تبدّل قاعدة بيانات" فقط، بل تبني طبقة Backend كاملة كانت Supabase توفرها مجاناً. هذا حجم عمل حقيقي إضافي — لكنه يمنحك تحكماً كاملاً بدون أي اعتماد على خدمة سحابية خارجية، وهو مناسب تماماً لموديل "يُباع مرة واحدة ويُستضاف عند الزبون" الذي ذكرته.

## البنية الجديدة

```
Flutter (Web/Desktop/Mobile)
        │  HTTPS + JWT
        ▼
ASP.NET Core Web API  ← يستضاف على نفس Windows Server (IIS)
        │  Entity Framework Core
        ▼
SQL Server  ← نفس السيرفر أو سيرفر منفصل
```

## عزل البيانات (Multi-Tenant) بدون Supabase RLS
SQL Server يملك ميزة مكافئة تماماً تسمى **Row-Level Security** (`CREATE SECURITY POLICY`)، لذلك **لم نفقد هذه الحماية** — فقط تغيّرت طريقة تفعيلها:
1. عند تسجيل الدخول، الـ API يصدر JWT يحمل `organization_id` و`branch_id`.
2. Middleware مخصص (`TenantContextMiddleware`) يقرأ هاتين القيمتين من التوكن في كل طلب.
3. قبل تنفيذ أي استعلام، يُنفَّذ `sp_set_session_context` على اتصال SQL Server الحالي بهاتين القيمتين.
4. دالة الحماية (`fn_TenantAccessPredicate`) المرفقة في `DATABASE_SCHEMA_SQLSERVER.sql` تفلتر كل صف تلقائياً بناءً على هذا السياق — **بنفس ضمان العزل السابق تماماً**، فلا توجد ثغرة أمنية جديدة نتيجة الانتقال.

## ما يتبقى بناؤه في الـ Backend (مسجَّل حتى لا يُنسى)
- `AuthController` — تسجيل الدخول، تجديد التوكن، تغيير كلمة المرور.
- Controller لكل موديول من `ARCHITECTURE.md` (المخزون، POS، العملاء، التقارير...) — النمط موحّد وموضّح في `ProductsController` و`InvoicesController` كمرجع.
- `NotificationsHub` (SignalR) — بديل Realtime لتنبيهات نقص المخزون والصلاحية.
- خدمة توليد وتفعيل مفاتيح الترخيص (مرتبطة بموديول License في المخطط).
